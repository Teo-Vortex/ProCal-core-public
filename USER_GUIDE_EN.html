ProCal - User Guide

1. Access and sign-in

Initial setup by the installation owner

  1. Open the ProCal Core address provided by the installation owner, for example http://server-ip:8080.
  2. On a new installation, open /setup. Enter the setup token stored as PROCAL_SELF_SETUP_TOKEN in the local .env file.
  3. The first account requires a username and a password of at least 8 characters. Nickname, full name, workplace, and job title are optional.
  4. The first account is always created as system_admin; the setup screen does not offer a role selector.
  5. If setup displays a service token after account creation, store it securely at once: it is shown only once and is not the sign-in password.

Registering a colleague

  1. The colleague opens the Core address and presses Create account.
  2. They enter a username, nickname, full name, workplace, job title, password, and password confirmation.
  3. After Register, the account remains pending and cannot sign in yet.
  4. An administrator opens Admin panel > Personnel, selects a role, and presses Approve. The same screen can suspend accounts, reset passwords, and assign individual permission overrides.
  5. After approval, the colleague signs in with their username and password. On first sign-in, they complete any requested profile details.
The setup token and passwords in .env are secrets for that installation. Do not publish them in GitHub, screenshots, chat, or bug reports. If ProCal is behind a reverse proxy or domain, configure the proxy, HTTPS, and allowed origins before inviting users.

2. Workspace overview

  • The top area contains the ProCal logo, connection status, and a compact Menu button. Notifications and chat sit next to the current user's name.
  • The left panel shows:
    • clock
    • date and weekday
    • current user
    • personal compensation balance
  • The main workspace has four primary modes: Calendar, Events, Notes, and Tasks.
  • The calendar itself has two data views:
    • Personal - personal records plus shared records visible to you
    • Shared - the team calendar
  • Day timeline and Next 10 entries can be collapsed. Their compact state leaves more room for the calendar, and pressing the title expands the content again.
  • The interface is responsive: on narrow screens the main panels rearrange, and detailed calendar views open as touch-friendly dialogs.

3. Menu

  • Profile - opens the current user's profile details.
  • User guide - opens this guide in a new tab.
  • Mobile app - opens the configured Android download page or file.
  • Report bug - opens the configured issue channel. In the public self-hosted build, this is GitHub Issues.
  • Open admin panel - visible only when the role allows it.
  • Logout - signs out of the realm.

Quick actions can show Media, Reports, Leave, Working time, Inventory, Compensations, and Files, depending on the role. A missing button usually means that the module or the required permission is not enabled for the current user.

4. Calendar

  • The workspace supports month and year views.
  • Prev, Next, and Today control the visible period.
  • Filters opens the filtering panel.
  • Compact Tasks indicators in each day summarize task status:
    • orange - open task
    • teal - ongoing work
    • green - completed task
    • red - overdue task
  • On desktop, hovering the indicator opens a compact preview that remains open while the pointer is over it. Pressing it opens a detailed dialog; touch screens use the dialog directly.
  • The compact preview includes dated tasks and a Working on section. Checkboxes complete or resume tasks you can manage, while Details opens the full task module.
  • Completed ongoing work remains visible in the calendar with a green indicator for the period from its start date through its completion date.
  • Clicking the free area of a day opens Selected day and its quick-add actions. The open button appears on hover without changing the cell height.
  • Inside Selected day, the Plan tab shows events and tasks, while Working time shows arrival, departure, and recorded time according to your permissions.
  • Next 10 entries shows the event date and time, or the date together with All day.

5. Events and tasks

Events

  1. Select a day and use Add event, or open Events mode to search and manage the event register.
  2. Enter a title, date, start and end time, or enable All day. Add a category, recurrence, participants, and description when needed.
  3. Use the Reminders tab to enable reminders and select their timing and recipients. Use Files to attach event files.
  4. Save the event. It appears in the calendar and in Next 10 entries; pressing it opens the full preview.
  • Events can have a time, be all-day, span multiple days, or repeat. The event preview also shows its date and time.
  • The Reminders tab enables reminders and controls when and to whom they are sent. A repeating event can apply reminders to every occurrence.
  • Recipients can include event participants, people assigned to tasks, all users, or a manually selected group.
  • The event preview includes buttons for:
    • Files
    • Program
    • Add task
    • Edit
    • Delete
  • Event tasks are shown as a checklist with their assignees. A user with permission can complete or resume them directly from the preview.
  • An event can have a dedicated Program file, usually a PDF.
  • The program opens in a new tab instead of forcing a download.

Tasks

  1. For a one-time action, select a day and press Add task. For longer work, open Tasks > Ongoing work, enter a title, start date, and category, then press Start work.
  2. Select the personal or shared calendar and add the responsible people. Personal-task invitees must accept; shared-task assignments are immediate.
  3. Finish a task with its checkbox or the Complete button. Ongoing work allows correction of its actual completion date and can be resumed later.
  4. Use the shared All / Active / Completed filters and, when permitted, Mine / All people.
  • The Tasks tab has shared All / Active / Completed filters and two lists: Ongoing work and Dated tasks.
  • A dated task is a specific action for one day. It can be completed or resumed with its checkbox and edited from the same list.
  • Ongoing work has a start date and remains active until it is finished. Its completion date can be corrected, and completed work stays in history and can be resumed.
  • Users allowed to read team tasks also receive a Mine / All people filter. Other users only see tasks in which they participate.
  • Every task in the shared calendar is visible to all users, including individually assigned tasks, team tasks, and event tasks, so the team can see who owns each responsibility.
  • Tasks created in a personal calendar are visible only to their owner and participants who accepted an invitation. They never appear in the shared calendar.
  • Assignment in a shared task is immediate. Adding someone to a personal task sends an invitation; the task enters their personal calendar only after acceptance. Declining does not change the owner's task.
  • Shared tasks and events also appear in the relevant users' personal calendars. Personal planning remains private from the rest of the team.
  • Event tasks remain visible in their event context and can have separate assignees.
  • A person's report uses the content of that person's personal calendar, whether generated by that person or by a manager with permission. Ongoing work is reported on its start date with either its completion date or an in-progress status.

6. Notes

  • The main panel can switch to Notes.
  • Press New note, enter a title and content, and save. The note actions let you edit, send, share, or delete it according to your permissions.
  • Notes support ownership, sending, and sharing.
  • The UI distinguishes between:
    • Owned
    • Shared with me
  • Notes remain available across all plans.

7. Files

  • The file module is realm-specific. Users only see files belonging to their own realm.
  • It uses a tree layout with system areas such as:
    • Events
    • Chat
    • Shared
  • Event folders are created automatically when files are attached to an event.
  • Inside Chat, each user sees the system folder for files received through chat.
  • The module shows current storage usage. Self-hosted ProCal can run without an application hard limit, but available disk space and the Docker volume still impose the real limit.
  • It supports:
    • upload
    • preview
    • download
    • creating/renaming/moving/deleting folders where permissions allow it

8. Chat and notifications

Chat

  • Opened from the top bar icon.
  • Supports conversations and file attachments.
  • Uses a dedicated unread badge.

Notifications

  • Opened from the bell icon.
  • Shows system and user-facing notifications based on realm configuration.
  • In-app Core notifications work without Firebase. Android push requires Firebase configuration by a system administrator.
  • Generic sends privacy-preserving text through Firebase; Detailed may include the notification title and body.

9. Reports and compensations

Reports

  1. Open Menu > Reports.
  2. Select a person and date range. A regular user can select themselves; a user with reports.read_all can report on other people.
  3. Press Generate report, review the result, and use Save PDF.

The report uses the records that belong to the selected person's personal calendar: their private entries, shared events and tasks in which they participate, absences, and ongoing work. Completed tasks use a status marker instead of strikethrough text.

Compensations

  • Compensations shows the personal balance and, with additional permission, the team overview.
  • A user with comp.manage can add overtime or absence for a selected person and date, enter a duration and reason, and make a separate adjustment.
  • The ledger preserves balance movements; adjustments should not be used to hide the original records.

10. Leave and absences

  • The menu opens the personal leave popup for the current user.
  • That panel shows leave balances, used days, and the personal absence calendar.
  • The user can submit leave/absence requests depending on permissions.
  • Approved absences appear in the main calendar. A request can be approved without a substitute when none is required.

11. Working time

Daily check-in

  1. Sign in with your own account. A QR/NFC entry is always recorded for the currently signed-in person.
  2. On arrival, open the Android app and hold the phone near the NFC tag, or press the global QR button and scan the station code. In Working time, choose the check-in button for your workplace. The clock menu beside notifications and chat offers the same actions.
  3. On departure, scan the same station again. The screen shows the last status, time, and station.
  4. Review your history in the module or open a selected calendar day > Working time.

Preparing a QR/NFC station

  1. An administrator with attendance.manage opens Working time and adds workplaces. When upgrading from an older version, historical entries and stations without a workplace are assigned to the first workplace added, preserving their history.
  2. In NFC / QR stations, enter a name and location, select an active workplace, and press Create station. Scanning records arrival at the station's workplace.
  3. Use Download QR to print the code. For NFC, press Copy and write the complete procal://attendance/... payload as an NDEF URI or UTF-8 Text record with an NFC-writing app. ProCal Android reads tags but does not program them.
  4. The open action shows the same active code. Use Create new code only for a lost or compromised QR/NFC tag because it immediately invalidates the old one.
  • Open Working time from the main menu to record check-in and check-out and review your personal workday log.
  • A scan records attendance for the user currently signed in to ProCal. An unauthenticated visitor cannot create an entry.
  • In the Android app, NFC is read automatically while the app is open. Scan a QR station from the global QR button in the top bar or from the module.
  • A station keeps its current code. Opening it does not rotate it; the separate new-code action invalidates the previous QR/NFC payload.
  • In the calendar, select a day and open Working time to see arrival, departure, the workplace for each entry, and recorded time for that day.
  • Users with all-attendance access see a team overview and history by person and date. Management permission additionally allows corrections, voids, and workplace and station administration. Deactivating a workplace stops new check-ins but preserves history and allows an open shift to check out.
  • Corrections and voids are added to the journal without overwriting the original entry.

12. Inventory

Initial preparation

  1. An administrator assigns inventory permissions under Admin panel > Roles. A user without inventory.read cannot see the module.
  2. Open Inventory > Locations and create the real warehouses, rooms, or zones.
  3. Press New item and enter a name, unique SKU, unit, category, initial location, and quantity. Set low-stock, critical-stock, and restock-target thresholds.
  4. Under Notifications, select the global channels, additional recipients, and reminder frequency for active alerts.

Daily operations

  1. Find an item by name/SKU or scan its QR code.
  2. Select Receive, Issue, Transfer, or Adjust/stocktake, enter the quantity and locations, and review the summary before Save movement.
  3. For a stocktake, use absolute quantity when entering the physically counted stock. A reason is required.
  4. Use Recent movements to audit the ledger. If an entry is wrong, press Correct; ProCal adds an opposite movement and preserves the original.
  • The Inventory module shows the item catalog, total stock, and stock by storage location.
  • Each item has a unique SKU/code, unit, category, and its own low and critical stock thresholds.
  • Depending on permissions, a user can receive, issue, transfer, or adjust stock. A stocktake adjustment can also set an absolute quantity. Negative results are rejected.
  • Recent movements opens a ledger with search and filters for operation, location, and period. Correct keeps the original movement and adds an opposite entry with a required reason.
  • The current QR opens the exact item, and the label includes its name and SKU. Opening the QR does not rotate it; the separate new-code button invalidates the previous code.
  • After scanning, ProCal opens the item and offers the permitted actions: receive, issue, or transfer.
  • Android uses its built-in scanner. Browser camera access depends on device support and a secure context; when unavailable, enter the payload manually.
  • A user with Inventory: settings permission selects global channels, recipients, and reminder frequency. Each item has separate thresholds and can disable its own alerts.
  • Permissions for viewing, items, receiving, issuing, transferring, stocktake, locations, and settings are assigned under Admin panel > Roles or as an individual permission override.

13. Media monitoring

  • The module is visible with media.read and tracks your own publications and discovered online mentions.
  • Under Our publications, add a title, valid URL, and publication date.
  • Under Discovered mentions, add a title, URL, and date and optionally link it to one of your publications.
  • The top area shows monthly KPIs and a heatmap. Navigate with Prev/Next and export permitted data as CSV or JSON.
  • Creation, editing, deletion, and export are controlled by separate media.* permissions.

14. Mobile app

  • The Android app is a secured shell around the same ProCal Core interface and does not keep a separate copy of calendar data.
  • On first launch, enter the Core address. You can save multiple servers and switch between them from server management.
  • The active browsing server and the notification source are separate. Only one saved server can deliver push notifications to the app at a time.
  • Public addresses must use HTTPS. HTTP is accepted only for localhost, private IP addresses, and local network hostnames.
  • The Mobile app button opens the APK or release page configured by the installation owner. Android may ask for permission to install from that source.
  • NFC is available only in the Android app. QR scanning works in Android and supported browsers.
An APK update must be signed with the same persistent key as the installed version. Do not install APKs from unknown or unverified sources.

15. Profile and password

  • The profile dialog stores:
    • nickname
    • full name
    • workplace
    • job title
  • Account management stays inside the local Admin panel.
  • Admins can approve users, reset passwords, change roles, suspend accounts, or hard-delete test accounts where appropriate.
  • On first entry, ProCal may require missing profile fields to be completed.

16. Admin panel

The local admin panel is the primary management surface for this self-hosted ProCal Core installation.

  • Personnel - users, approvals, roles, password resets, and permission overrides.
  • Roles, Categories, Holidays, Leave Form.
  • Notifications - local rules, records, and Android push. For Firebase, upload both the service account JSON and Android google-services.json, then select Generic or Detailed payload.
  • Audit - records administrative and sensitive actions.
  • Files - storage monitoring and chat file retention.
  • Backups - encrypted full/working exports and temporary upload validate/restore; no server-side realm backup catalog.
  • Updates - version checks, one-button update, and rollback when the installation includes the updater container.
The Firebase service account is a secret. ProCal encrypts it on the server and never returns it to the browser, Android app, or backup export. Do not send its contents through chat or support requests.

17. Updates, backups, and support

  • Report bug opens the configured issue URL. The public build uses GitHub Issues by default; another installation may use its own URL or a local report.
  • For image-based installations with the updater, a system administrator can check versions and start an update from Admin panel > Updates. Database and files remain in persistent Docker volumes.
  • The updater checks application health and automatically rolls the app image back after a failed start. A manual image rollback cannot reverse database migrations that already ran.
  • Before updates or major changes, export an encrypted full backup and store the backup file and its key PDF separately.
  • ProCal does not keep a server-side catalog of realm backups. A file uploaded for validation or restore is temporary and deleted after the operation.
  • If the UI behaves strangely after an update, test with Ctrl + F5 first.
Restore is destructive for current data. Use your encrypted backup file and matching key; the uploaded restore copy is deleted after the operation.
